# 翻譯、來源與覆核紀錄

正文由英文原書逐頁翻譯。機翻檔未讀取或採用。

## 檔案

| 檔案 | 用途 |
| --- | --- |
| `sources.json` | 英文來源版本、總頁數、完整 PDF SHA-256。 |
| `coverage.json` | 每頁來源及中文正文的 SHA-256、字元數與對應檔案。 |
| `editions.json` | 玩家／GM 各區章節與頁數；共用規則在兩區皆可讀。 |
| `resource-inventory.json` | 核心書以外五份英文PDF的狀態、對應正文、版本差異與檔案指紋。 |
| `context.json` | 全書架構、核心機制與來源政策的工作脈絡。 |
| `reviews.json` | 已覆核頁面、覆核種類與報告索引。 |
| `review-records/` | 不同工作單元逐頁讀完英文及譯稿後的原始語義初校紀錄。 |
| `resolutions.json` | 已修正問題、具體處理方式與修正後正文指紋。 |
| `integration-changes.json` | 跨章術語及裝備標籤統一記錄。 |
| `source-issues.json` | 原書本身的不一致、舊引用與未決歧義；與誤譯分開記錄。 |

## 狀態定義

- `translated`：對應來源頁的中文內容已寫入，不等於校訂完成。
- `first-pass-complete`：另由不同翻譯工作單元進行逐頁語義初校，且已處理其可行動的問題。
- 原始報告中的 `pass=false` 保留當時判斷；修訂記於 `resolutions.json`，不改寫歷史讓報告看起來一開始就通過。

目前完成的是 AI 翻譯與一次獨立工作單元初校，並非人類出版級終校。結構、頁面對應、搜尋與資源檢查不會被當成語義正確的替代證據。單靠中文／英文長度比例，也不能判定完整性。

## 修訂

先改 `content/pages/` 的唯一正文，再直接核對相關英文頁面。若改動已綁定的修正，更新修訂紀錄、對應指紋與覆核說明；保留原始覆核快照。執行 `python scripts/build.py` 與 `python scripts/validate.py`，再發布。

全新 checkout 沒有原書抽字檔，建置會保留既有來源指紋；不能以此宣稱已重新讀取原文。如果來源 PDF 版本變更，須重新提取、比對來源指紋與頁面，重新處理受影響的翻譯及覆核。
